# 古着コーデ相談ボット 開発ドキュメント

## プロジェクト概要

本プロジェクトは、Difyで作成したチャットボットとAPI連携し、AIチャット機能を持つWebアプリを構築するものである。エンジニアリング学習の課題2として取り組み、副次的にポートフォリオ用途も想定している。

### 作るもの
古着コーディネートの相談ができるAIチャットボットWebアプリ。ユーザーが手持ちのアイテムや予算、シーンを伝えると、古着ならではのジャンル知識(90年代〜Y2K、アメカジ、ミリタリー、ワークウェア等)を活かしたコーデ提案を返す。

### なぜこのテーマを選んだか
私は本業とは別に、フリマアプリで古着の個人販売を行っている。汎用的なチャットボットを作るより、自分の事業ドメインに関連するテーマを選ぶことで、以下のメリットがあると考えた。

- ポートフォリオとして語る時に、事業背景と技術力の両方を見せられる
- 実際に自分が改善のためにユーザーになれるので、改善サイクルが回しやすい
- 将来的に自分の販売活動の顧客向け機能に発展させる可能性がある

## 技術スタック

### フロントエンド
- Vite + React + TypeScript
- Tailwind CSS
- localStorage(会話履歴とconversation_idの永続化)

### バックエンド(Dify側)
- Dify Cloud版(チャットフロー型アプリ)
- モデル: gpt-5.5

### 連携方式
- フロントエンドから直接Dify APIを呼び出す方式を採用
- 将来的な本番運用時は、既存のFastAPI中継サーバーを経由する構成に切り替え可能な設計

### 開発ツール
- Bolt.new(UI設計フェーズ)
- Cursor + Claude Code(API連携以降の実装)
- GitHub(yurin02リポジトリ)
- Render(将来のデプロイ先として想定)

## 全体の開発フロー

1. Difyで新規チャットフローアプリ作成、プロンプト設計
2. Boltで段階的にチャットUI構築(Prompt 1〜3)
3. GitHubを経由してCursorへ環境移行
4. Cursor内でDify APIとの連携実装
5. ポートフォリオ用の整備
6. Renderへのデプロイ

## 意思決定の要約

開発を進める中で、いくつかの分岐点で判断を行った。詳細は各フェーズのドキュメントに記載する。

- 既存の経費ボットのAPIキー流用 vs 新規Difyアプリ作成 → 新規作成を選択
- 直接呼び出し vs FastAPI中継サーバー経由 → 直接呼び出しを選択(課題スコープ優先)
- Boltの複数アカウント運用 vs 本垢待ち → 最終的に本垢統一で完走
